# 02 · L1 数据模型与表结构

> **日期**：2026-07-15
> **前置条件**：PostgreSQL 18 已上线（用户确认）。Skip Scan / UUIDv7 / 虚拟生成列均依赖 PG18。
> **迁移方式**：Flyway 版本化迁移（废弃旧 `pg18-migration.sql` 的"不接入 Flyway"做法）。

## 1. 实体关系总览

```
gb_standard (标准)
  ├── domain_schema JSONB ── 定义 4 槽位在本标准的标签/取值（领域无关骨架）
  ├── 1:N → gb_clause (条款)
  │          ├── 4 个固定语义槽位列（primary_type / secondary_type / quantity_value / condition_text）
  │          ├── 物化路径 clause_path (章→条→款层级树，虚拟生成列拆解)
  │          ├── polarity / exception_of（极性，根因 9）
  │          ├── 1:N → gb_parameter (参数/公式)
  │          └── N:M → gb_reference (引用关系)
  ├── 1:N → gb_term_dict (术语同义词)
  └── 关联 → airag_embedding (向量 chunks，通过 chunk_id 反查)
gb_audit_log (审计) ── 从 P2 起写入，横切所有层
```

## 2. 固定语义槽位（核心设计）

### 2.1 为什么是 4 个固定槽位

所有技术规范文档（国标/行标/企标）都有四个共性维度——"做什么 / 对谁 / 多少 / 什么条件"。这是规范文档的**元结构**，不是电池知识：

| 槽位列 | 语义角色 | 类型 | 电池 GB31241 | 储能 GB/T34131 | 消防 GB |
|--------|---------|------|-------------|---------------|---------|
| `primary_type` | 做什么（测试/功能类别） | VARCHAR | overcharge | BMS功能 | 耐火试验 |
| `secondary_type` | 对谁（对象/适用物） | VARCHAR | cell | LiFePO4 | 防火门 |
| `quantity_value` | 多少（量值） | NUMERIC | 3 (串) | 100 (Ah) | 1.5 (h) |
| `condition_text` | 什么条件下 | VARCHAR | 25±5℃ | -20℃ | 常温 |

**关键**：列名固定 → 可建 B-Tree 索引 → PG18 Skip Scan 命中。领域差异全在**值**里，不在键名里。

### 2.2 与 domain_schema 的分工

| 归属 | 存哪 | 作用 |
|------|------|------|
| 4 槽位的**值** | `gb_clause` 的 4 个固定列 | 检索过滤、Skip Scan 索引 |
| 4 槽位的**语义说明**（label/enum/unit） | `gb_standard.domain_schema` JSONB | LLM 抽取时校验取值合法性、前端展示标签 |

domain_schema **不参与检索过滤**，只服务 LLM 抽取和展示。

### 2.3 超过 4 维怎么办（渐进式扩展）

- 95% 条款 4 槽位够用。
- 极少数超长尾（如某条款同时有温度+湿度+压力+时间+电压 5 个条件）→ 写入 `metadata` JSONB，用 **GIN 索引** `@>` 兜底。
- 若某第 5 维度**高频出现**（通过 audit log 统计发现），升级为 `slot_5` 固定列（不破坏存量，渐进加列）。

## 3. 表结构

### 3.1 gb_standard — 标准实体

```sql
CREATE TABLE gb_standard (
    id              UUID PRIMARY KEY DEFAULT uuidv7(),
    standard_no     VARCHAR(50) NOT NULL,        -- 'GB 31241' / 'GB/T 34131'
    version         VARCHAR(20),                 -- '2022' / '2014'
    full_name       TEXT,                         -- '便携式电子产品用锂离子电池...'
    publish_date    DATE,
    implementation_date DATE,
    withdrawal_date DATE,                         -- null = 现行
    status          VARCHAR(20) DEFAULT 'current',-- current / superseded / withdrawn
    domain          VARCHAR(100),                 -- 领域标签（自动推导或人工标注）
    knowledge_id    VARCHAR(36),                  -- 关联 airag_knowledge 表
    doc_id          VARCHAR(36),                  -- 关联 airag_knowledge_doc 表
    supersedes      TEXT[],                       -- 替代的旧标准 {'GB 31241-2014'}
    normative_refs  TEXT[],                       -- 第2章规范性引用文件清单
    domain_schema   JSONB DEFAULT '{}',           -- 【核心】4 槽位的标签/取值定义
    metadata        JSONB DEFAULT '{}',
    parse_status    VARCHAR(20) DEFAULT 'UPLOADED',-- 见 §3.7 状态机
    pdf_url         VARCHAR(500),
    markdown_content TEXT,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(standard_no, version)
);
```

### 3.2 gb_clause — 条款实体（含 4 固定槽位 + 层级树）

```sql
CREATE TABLE gb_clause (
    id              UUID PRIMARY KEY DEFAULT uuidv7(),
    standard_id     UUID NOT NULL REFERENCES gb_standard(id),
    clause_path     VARCHAR(50) NOT NULL,         -- '9' / '9.2' / '9.2.3'
    parent_path     VARCHAR(50),                  -- '9.2' (9.2.3 的父条款)
    depth           INT NOT NULL,                 -- 1=章, 2=条, 3=款
    title           TEXT,
    clause_type     VARCHAR(30),                  -- normative/informative/scope/reference/definition
    polarity        VARCHAR(20) DEFAULT 'positive',-- positive/negative/exception（根因9）
    exception_of    VARCHAR(50),                  -- 例外针对的条款路径
    requirement_strength VARCHAR(20),             -- mandatory(应)/recommended(宜)/permissible(可)
    is_scope        BOOLEAN DEFAULT false,
    is_appendix     BOOLEAN DEFAULT false,
    appendix_label  VARCHAR(10),                  -- 'A'/'B'/'C'

    -- 【核心】4 个固定语义槽位（领域无关）
    primary_type    VARCHAR(100),                 -- 做什么
    secondary_type  VARCHAR(100),                 -- 对谁
    quantity_value  NUMERIC,                      -- 多少
    condition_text  VARCHAR(200),                 -- 什么条件

    text            TEXT NOT NULL,
    page_no         INT,
    chunk_id        VARCHAR(100),                 -- 关联 airag_embedding
    metadata        JSONB DEFAULT '{}',           -- 超长尾字段兜底（GIN 索引）
    created_at      TIMESTAMPTZ DEFAULT NOW()
);
```

### 3.3 gb_parameter — 结构化参数/公式

> ⚠️ 公式结构化存储，**不全信任 LLM 字符串**（根因 2 + 安全）。

```sql
CREATE TABLE gb_parameter (
    id              UUID PRIMARY KEY DEFAULT uuidv7(),
    standard_id     UUID NOT NULL REFERENCES gb_standard(id),
    clause_id       UUID NOT NULL REFERENCES gb_clause(id),
    param_name      VARCHAR(100),                 -- 'overcharge_threshold'
    formula_display TEXT,                         -- 'U = n × 6.0 V'（仅供展示，不 eval）
    param_value     NUMERIC,                      -- 静态值（LLM 抽出的具体数值，可空）
    unit            VARCHAR(30),                  -- 'V'/'A'/'℃'/'min'
    variables       JSONB,                        -- [{"name":"n","desc":"电池串数"}]（变量绑定）
    condition_expr  TEXT,                         -- 'n_cells > 1'
    source_text     TEXT,                         -- 原始文本片段
    metadata        JSONB DEFAULT '{}',
    created_at      TIMESTAMPTZ DEFAULT NOW()
);
```

**注意**：废弃旧 `pg18-migration.sql` 里的 `gb_param` 表（命名冲突 + 公式焊进 DDL）。统一用 `gb_parameter`。

### 3.4 gb_reference — 统一引用关系（标准内 + 跨标准）

```sql
CREATE TABLE gb_reference (
    id                  UUID PRIMARY KEY DEFAULT uuidv7(),
    source_standard_id  UUID NOT NULL REFERENCES gb_standard(id),
    source_clause_path  VARCHAR(50) NOT NULL,
    target_type         VARCHAR(20) NOT NULL,     -- 'intra'(标准内) / 'inter'(跨标准)
    target_standard_id  UUID REFERENCES gb_standard(id),
    target_standard_no  VARCHAR(50),              -- inter 时的目标标准号
    target_clause_path  VARCHAR(50),
    ref_type            VARCHAR(30),              -- normative_reference/prerequisite/informative
    ref_text            TEXT,
    created_at          TIMESTAMPTZ DEFAULT NOW()
);
```

### 3.5 gb_term_dict — 术语同义词表

```sql
CREATE TABLE gb_term_dict (
    id              UUID PRIMARY KEY DEFAULT uuidv7(),
    standard_id     UUID REFERENCES gb_standard(id), -- null = 全局术语
    canonical_term  VARCHAR(100) NOT NULL,
    synonyms        TEXT[] NOT NULL,
    definition      TEXT,                         -- 从第3章提取
    domain          VARCHAR(100),
    created_at      TIMESTAMPTZ DEFAULT NOW()
);
```

### 3.6 gb_audit_log — 审计追溯表（从 P2 起写入）

```sql
CREATE TABLE gb_audit_log (
    id                  UUID PRIMARY KEY DEFAULT uuidv7(),
    session_id          VARCHAR(50),
    user_query          TEXT NOT NULL,
    routing_intent      VARCHAR(30),              -- CLAUSE_LOOKUP/PARAM_QUERY/SEMANTIC_SEARCH
    extracted_slots     JSONB,                    -- 4 槽位抽取结果
    retrieval_channels  TEXT[],                   -- ['vector','structure','param']
    retrieved_clauses   JSONB,                    -- 命中条款列表
    llm_response        TEXT,
    cited_sources       JSONB,                    -- 引用的标准号/条款号
    tool_calls          JSONB,                    -- Tool 调用记录
    latency_ms          INT,
    success             BOOLEAN,
    created_at          TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_audit_session ON gb_audit_log(session_id, created_at DESC);
```

### 3.7 文档状态机（airag_knowledge_doc.parse_status）

```
UPLOADED → PARSING → PARSED → CONFIRMED → INDEXING → COMPLETED
                         ↑                     │
                         └── 用户驳回，重新解析 ──┘ (回到 PARSING)
```

- `PARSED`：MinerU + 结构解析完成，等待用户确认（LLM 抽取**尚未**开始）。
- `CONFIRMED`：用户确认结构无误，触发 LLM 批量抽取。
- 关键设计：**LLM 抽取在 CONFIRMED 之后**，避免在错误结构上白跑 LLM。

## 4. 索引策略（PG18 三件套）

### 4.1 Skip Scan 多列索引（主力，命中固定槽位）

```sql
-- gb_clause 的 Skip Scan 索引：覆盖通用骨架 + 4 槽位
CREATE INDEX idx_clause_skip ON gb_clause
    (standard_id, primary_type, secondary_type, clause_path, polarity, status);

-- PG18 Skip Scan：WHERE primary_type='overcharge'（跳过 standard_id）仍走索引
-- 适用根因：1、6、9（精确定位 + 极性过滤）

-- gb_clause 层级索引
CREATE INDEX idx_clause_path   ON gb_clause(standard_id, clause_path);
CREATE INDEX idx_clause_parent ON gb_clause(standard_id, parent_path);
```

### 4.2 GIN 索引（兜底超长尾动态字段）

```sql
CREATE INDEX idx_clause_metadata_gin ON gb_clause USING GIN (metadata);
CREATE INDEX idx_standard_schema_gin ON gb_standard USING GIN (domain_schema);
```

### 4.3 虚拟生成列（领域无关派生，PG18）

```sql
-- clause_path 拆解为 chapter（领域无关的路径深度索引）
ALTER TABLE gb_clause
    ADD COLUMN chapter VARCHAR
    GENERATED ALWAYS AS (split_part(clause_path, '.', 1)) VIRTUAL;
CREATE INDEX idx_clause_chapter ON gb_clause(standard_id, chapter);
```

> ⚠️ 虚拟生成列**只用于领域无关的派生**（如 chapter）。电池公式 `n*6.0` 不进 DDL，存 `gb_parameter` 表。

### 4.4 UUIDv7 主键（时间有序，B-Tree 友好）

所有表主键 `DEFAULT uuidv7()`。PG18 原生函数，时间有序，按时间召回最新版本天然高效（根因 7）。

旧的 `gb_standard_indexes_correct.sql`（字段已对齐实体）可保留作参考，但**正式索引以本节 §4 为准**。旧 `gb_standard_indexes.sql`（字段名 bug）已列入删除清单（见 `00-README §5.2`）。

## 6. 与 airag_embedding 的关系（不替代，只增强）

- `airag_embedding`（现有向量表）保持不变。
- `gb_clause.chunk_id` 关联 `airag_embedding` 的 chunk。
- 入库时双写：结构化信息进 gb_* 表；向量 chunk 进 airag_embedding，metadata 注入 4 槽位 + clause_path + standard_no。
- 检索时：VectorChannel 查 airag_embedding（用 metadata 过滤），StructureChannel/ParamChannel 查 gb_* 表。
